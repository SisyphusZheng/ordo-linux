# ADR 0006 — 桌面栈选型：KDE

- 状态：**已被 ADR 0009 取代（2026-11-21）**
- 日期：2026-11-19
- 取代原因：KDE Wayland 存在三个 KWin 专有缺陷，其中中文输入失效无法规避
  （同一 VM、同一 fcitx5 环境下 niri 正常，指向 KWin 的 input-method-v2 缺陷）。
  评估见 `0009-桌面栈终审-niri.md`。
- 背景：GNOME 50 + OpenRC 依赖第三方会话桥（gnome-session-openrc），Forge 扩展稳定性不足，CSD 窗口按钮反复异常。为修复该链路评估了四轮替代方案（Hyprland+Quickshell → niri → dwm/dwl），均基于主树与 GURU 的实测数据。验收标准确定为：支持 Flatpak 且可完成日常工作，不以视觉效果为目标。

## 一、决策

**默认桌面 = KDE Plasma**（plasma-desktop + sddm，143 包），GNOME 共存保留，KDE 验证满意后移出 world。

候选实测对照（2026-11-19）：

| 候选 | 打包状态 | Flatpak/portal | 开箱可用 | 裁决 |
|---|---|---|---|---|
| **KDE Plasma** | 主树 kde-plasma/* 官方团队维护；OpenRC 走 elogind 一等公民路径 | xdg-desktop-portal-kde 全套 | 文件管理器/设置/托盘/通知全带 | **采纳** |
| GNOME（现状） | 会话层依赖志愿桥，上游 issue #8 实证脆弱 | portal-gnome 完整 | 全带但链路脆 | 共存 → 退役 |
| niri | GURU 26.04，`KEYWORDS="~amd64"`（无 arm64） | 需自拼 portal 栈 | 只给合成器 | L3 第二会话实验候选 |
| Hyprland + Quickshell | 志愿 overlay，hypr* 生态 10+ 包互咬 | 需自拼 + 自写 shell | 只给合成器 | 否决（维护面） |
| dwm (X11) / dwl | 主树（dwm arm64 稳定，dwl ~arm64） | X11 架构死路 / portal 缺失 | 无通知、托盘、设置 | 思想宝库，不进产品 |

## 二、为什么"能干活"这个标准指向 KDE

1. **Flatpak 的实际可用性 = portal 栈完整性**。文件对话框、通知、截屏录屏、主题跟随、输入法桥接，每一项都由 `xdg-desktop-portal-*` 与 DE 深度集成。KDE 的 portal-kde 是官方维护的一等公民；平铺 WM 的每一项都要手工拼装，质量参差且无契约。
2. **会话层契约**：KDE 在 OpenRC 上走 elogind 官方路径（`REQUIRED_USE="^^ ( elogind systemd )"`），把"追上游 issue"的技术债换成"走正常 Gentoo bug 流程"。
3. SSD 服务端装饰解决 CSD 窗口按钮问题；KWin 原生平铺替代 Forge Shell 扩展（API 稳定性：合成器层优于 Shell 扩展层）。

## 三、光谱定位（四轮探索的闭环）

```
自建自由度  quickshell > dwl > niri ≈ hyprland > ── KDE ──
开箱可用度  quickshell < dwl < niri ≈ hyprland < ── KDE ──
                                              ↑ Ordo 选这端
```

suckless 系列说明了薄的边界：薄不等于可用。这与「委托优于自研」公理一致。

## 四、不引入清单

与 `deviations.md` §六 同一原则：显性否决须在决策阶段确定。

| 包 | 裁决 | 理由 |
|---|---|---|
| plasma-login-manager | 否 | 硬依赖 sys-apps/systemd[pam]（ebuild DEPEND 行），base mask 注明 "Needs systemd"，OpenRC 系统装不了 |

## 五、后果

1. 执行序：批次 1（138 包）→ SDDM/GDM 并存验证 → 批次 2（plasma-desktop）→ 中文输入（fcitx5 优先）/ Flatpak portal / 终端栈重建 → doctor 增 SDDM/KWin 检查项
2. GNOME 验证期后移出 world（届时在 deviations.md 登记）
3. niri 保留为 L3 x86 真机可选第二会话；其 aarch64 keywording 贡献票须先走七项验证流程（见 `deviations.md` §五）
4. **Flatpak 验收标准进 doctor**：portal-kde 在位 + `flatpak run` 冒烟测试——"桌面真好看然后结束"被制度化排除
5. Wayland-first 不动摇：dwm(X11) 的否决理由是架构层面的，与个人偏好无关
