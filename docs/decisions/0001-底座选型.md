# ADR 0001 — 为什么底座选 Gentoo

- 状态：已采纳
- 日期：2026-11-14

## 背景

需求（按权重）：
1. **可回滚**（开机能退回去）
2. **配置统一**（一台机器 = 一份文本）
3. **ZFS 原生**
4. **不要 systemd**
5. Flatpak 优先、中文开箱、国内镜像可达
6. 有辨识度（不做"又一个 X 的配置"）

## 候选

| 底座 | 回滚 | ZFS | 非 systemd | 国内镜像 | 赛道拥挤度 |
|---|---|---|---|---|---|
| **Gentoo** | ZFS + ZFSBootMenu（可做） | 原生支持 | 支持 | 支持 | 低 |
| Arch/Artix | 需自建 | 需 AUR 与 DKMS | 是 | 是 | 高 |
| NixOS | 代际 | 原生支持 | 否 | 是 | 极高 |
| Fedora/Bluefin | 镜像 | 无（许可原因） | 否 | 是 | 高 |
| FreeBSD | BE | 原生支持 | 是 | 部分 | 低 |

## 决策

选 **Gentoo**。

理由：
- 唯一能同时满足 1–5 的底座；
- 与 6 直接相关：目前没有任何"产品化的 Gentoo 桌面发行版"，位置是空的；
- ZFS 与内核一同编译，规避 Fedora 的 kmod 断链问题；
- OpenRC 原生，不需要 elogind 之类的"补丁生态"以外的妥协（GNOME 仍需 elogind，但属可控范围）。

## 代价（已知并接受）

1. **必须自建 binhost**，否则用户就是在编译 Gentoo；
2. GNOME + OpenRC 的组合边缘，需要自己趟（elogind、portal、电源）；
3. ZFS root 的引导链（initramfs + ZFSBootMenu）需要自研脚本；
4. 维护是长期承诺。

## 后果

- L1 阶段不追求"用户装得上"，只追求"我们自己装得对"；
- binhost 与 ISO 放到 L2/L3；
- 若 L1 验证发现 GNOME + OpenRC 不可接受，回退方案是 **Artix + OpenRC**（放弃 ZFS root 的原生性）。
