# ADR 0009 — 桌面栈：niri + ashell + xwayland-satellite

- 状态：**已被 ADR 0011 取代**（2026-11-22 迁移到 Noctalia 全家桶）
- 日期：2026-11-21
- 取代：ADR 0006（桌面栈选型 KDE）
- 关联：deviations #40–#49

## 一、问题陈述

ADR 0006 选定 KDE Plasma。实测发现三个 KWin 专有缺陷，其中两个无法规避：

| 缺陷 | 结论 |
|---|---|
| 中文输入失效 | KWin 的 input-method-v2 缺陷。对照实验：同一 VM、同一 fcitx5、同一配置下 niri 正常（拼音预编辑与 rime 候选词可用） |
| Polonium 平铺 | 依赖 KWin 脚本，与滚动平铺目标不符 |
| KRunner 玻璃效果 | KWin 6.8 无对应配置项 |

需求清单为：100% Wayland、开箱中文、轻量桌面、偏好 Rust、薄、功能完整、100% Flatpak、可视化商店、类 rofi 启动器。

KDE 仅部分满足前两项，需重新选型。

## 二、候选评估

| 候选 | 结论 | 原因 |
|---|---|---|
| Hyprland | ✗ | **15 个包全不在 Gentoo 树**（hyprland/aquamarine/hyprutils/...）。自写 15 个 ebuild 违背 thin |
| COSMIC | ✗ | Rust 但生态早期；且是完整 DE，超出"轻度" |
| quickshell | ✗ | 用户明确否决："不切换到 quickshell，因为为数不多的差异点会被毁灭" |
| **niri** | **✓ 采纳** | Rust / 纯 Wayland / 滚动平铺 / 在 Gentoo 树 / 配置为 KDL 纯文本 |

## 四、为什么 ashell 而不是 waybar

初版用 waybar（C++），能跑，但有三处硬伤：

1. **工作区靠轮询桥接**：waybar 每 1 秒 fork 一次 `niri msg` 拿工作区状态，是纯粹的开销。ashell 直接连 niri IPC（`NIRI_SOCKET`）。
2. **dock 实例烧 83% CPU**：waybar 的 `image` 模块每次重绘都重新解码 SVG，实测 2h42m 累计 83%。
3. **无内建设置面板**：音量/网络/蓝牙/亮度全要自己写脚本拼。

ashell 实测：**0% CPU / 55.9 MB**，且自带设置面板、通知中心、OSD、媒体播放器、热重载。

### 4.1 ashell 的四条隐性规则（全部踩过）

| # | 规则 | 违反后果 |
|---|---|---|
| 1 | 枚举值必须 PascalCase（`Top` / `Islands` / `Workspaces` / `Tempo` / `Cpu`） | TOML 解析失败，报错只给行号不给字段名 |
| 2 | `center` 不能为空数组 | 布局高度塌陷，**整条栏不可见**（进程和 layer 都还在） |
| 3 | `["A","B"]` = 两个胶囊；`[["A","B"]]` = 一个胶囊 | 布局与预期不符 |
| 4 | 手动启动必须 `export NIRI_SOCKET` | 报 `No supported compositor backend found` |

## 五、关键取舍

| 取舍 | 决定 | 理由 |
|---|---|---|
| dock 动画（悬停放大） | **放弃** | 需 quickshell QML 实时鼠标事件；用户已否决 quickshell |
| X 形连接线装饰 | **放弃** | 同上，niri 无对应机制 |
| 运行中应用指示点 | **放弃** | 需读 toplevel-management 协议，waybar/ashell 均不支持 |
| dock 居中限宽 | **放弃** | waybar 的 `margin-left/right` 在 layer-shell 下不可用；ashell 用 Islands 风格后此问题消失 |

## 六、修正记录（2026-11-21）

本 ADR 初稿曾把 ashell / xwayland-satellite 判为「永久放弃」，理由是「clang-22 编不完」。**这个结论是错的**：

- 根因为 ZFS ARC 未设上限（deviations #48）：8 GB VM 上 ARC 占用 6.7 GB，用户态仅剩 1.2 GB，
  编译 clang 时触发 direct reclaim 停滞。
- 修复 ARC 后：clang-22.1.8 于 45 分钟完成编译（此前停滞 50 分钟未完成），
  ashell 与 xwayland-satellite 各约 2 分钟安装完成。
- 附带确认：`libclang.so` 位于 `/usr/lib/llvm/22/lib64/`，此前判断为系统缺失系路径错误。

结论：编译期出现「进程仍在运行但无进展」时，先检查 `zfs_arc_max` 与 `nproc` 是否与 `MAKEOPTS` 匹配。
该状态的特征为 vCPU 满载、磁盘无写入、网络无响应。

## 九、登录管理器（2026-11-21 修订）

原方案为 SDDM。实测其依赖连带 13 个 `dev-qt` 包与 26 MB Qt6 库，
且自定义主题需维护 618 行 QML（deviations #36/#37/#38 均出自该主题）。

改为 **greetd + tuigreet**：

| 项 | SDDM | greetd + tuigreet |
|---|---|---|
| 依赖包 | Qt6 全家桶 | 4 个 |
| Qt 库 | 26 MB | 0（保留 qtbase/qtwayland 供 fcitx-qt） |
| 界面 | 图形（QML 主题） | 终端文字 |
| systemd 依赖 | 无 | 上游只提供 systemd unit，OpenRC 服务自备 |

上游 greetd 仅提供 `greetd.service`，OpenRC 服务文件位于 `config/desktop/greetd/greetd.initd`。
greetd 自行管理 VT 切换，不经 display-manager 包装脚本，两者互斥。

代价：登录界面为终端文字，不再是图形。
