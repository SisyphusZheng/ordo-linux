# 迁移脚本

> 已装机系统的「增量升级」路径。`install.sh` 只解决「从零」，本目录解决「从旧到新」。

## 契约

- 文件名：`<unix 时间戳>-<短描述>.sh`，时间戳是**首次提交的时刻**（`date +%s`）。
  按文件名字典序 = 按时间序执行，不需要额外索引。
- 每个脚本必须是 **幂等** 的：重复执行不产生副作用。执行记录在
  `/var/lib/ordo/migrations/<文件名>.done`，存在即跳过。
- 脚本以 root 运行，`set -eu`，只用 POSIX sh。
- 脚本**只调用 `ordo` 子命令或做文件级操作**，不重新实现业务逻辑
  （逻辑在 `scripts/` 里，迁移只是「什么时候调用它」）。
- 失败即停：某个迁移非零退出，`ordo migrate` 立刻中止并保留后续未执行。

## 为什么要有这个

`config/` 是唯一事实来源，但「唯一事实来源改了」和「机器上的东西变了」
是两件事。没有本目录，每次改进都只对「下一次重装」生效——等于把已装机的
用户锁死在装机那一天。Omarchy 用 308 个时间戳迁移解决同一个问题。

## 示例

```sh
#!/bin/sh
# 2026112101-orld-notes-split.sh — world 去注释化后的兼容处理
set -eu
# 旧机器的 /var/lib/portage/world 带着行内注释，Portage 会报错；
# 用新的声明重写一遍。
ordo config apply world
```
